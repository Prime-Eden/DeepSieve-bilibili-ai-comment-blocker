# HANDOFF · DeepSieve 交接文档

> 本文档由 Claude（claude.ai 审核 agent）的审核发现 + WorkBuddy 接手 agent 的实施状态合并而成，用于多 agent 之间的工作交接。最后更新：2026-11-16（v2.16.5）。

## 背景

| 5 | 人工强化把「Lv2 新号」「默认头像」等账号静态基础特征也计数——学了基础特征而非区分度，推高误杀 | ✅ v2.15.0 已修（基础比例校准：强化只收文本/行为特征，排除 level/avatar/mid/manual） |

## v2.16.4 修复（二次审阅发现，v2.16.3 上的回归与遗漏）

| # | 问题 | 修复 |
|---|---|---|
| 1 | Chrome 上精判开关从不申请 `api.deepseek.com` 权限：申请代码挂在 `askConsent()` 之后，而它在 Chrome 返回 null，整段不执行；且 `permissions.request` 放在 await 之后会丢失点击手势 | popup.js 改为在点击处理里同步直接申请，拒绝则回滚开关 |
| 2 | API Key 脱敏只在启动时做一次，`onChange` 里重新合并设置后真实密钥又回到页面脚本 | content.js 每次重载设置都再脱敏 |
| 3 | Firefox 遗留代码未删净（见上表 4） | 已删 |
| 4 | 部分 `postMessage` 仍用 `'*'`，接收端也没校验 `e.origin` | 发送统一 `location.origin`；comments / counter / main-world 接收端补 origin 校验 |
| 5 | 撤销窗口代码为 3 秒，popup 文案与本文档写 5 秒 | 文案与文档改 3 秒 |
| 6 | 关闭状态下加载页面后再开启：空间页路由检测未启动，主世界不重送评论 | 路由检测常驻（仅启用时执行）；关闭→开启时补发 rescan |

> 以上均为静态阅读 + 语法检查 + content.js 的 mock 测试（密钥脱敏、关→开流程）；popup 授权流程需在 Chrome 里实机验证。

## v2.16.5 页面内 UI 精修（悬浮台 / 拉黑按钮 / 计数条）

> 验证方式：无头 Chrome + 模拟评论区 DOM（用源码里的真实 CSS 渲染，浅色 + 深色各一轮），非实机 B 站。

| 项 | 问题 | 处理 |
|---|---|---|
| 悬浮台面板 | **深色模式底色失效**：`.dk` 加在 `.menu` 自身，而样式写成 `.dk .menu`，永远选不中，面板在深色下仍是白底 + 浅色字 | 全部颜色改为 CSS 变量，深色只改变量（`.menu.dk`） |
| 分数条 | 四档条全是灰色且不居中，「可疑」标签基线偏低（字体回退导致行高不一） | 4 列网格 + 轨道 + 按档着色，固定行高 |
| 面板层级 | 大红数字抢眼、按钮描边过重、灵敏度三个独立描边按钮 | 数字用主文字色；次要按钮改浅底；灵敏度改分段控件；宽度 258→276 |
| 悬停「拉黑」按钮 | 常驻高饱和红底，视觉攻击性强 | 平时是中性浅灰胶囊，悬停才变危险红；「撤销」态加 3 秒倒计时细条（遵循 reduced-motion） |
| 可疑徽标 | 一枚小徽标里灰/蓝/红三色并存；按钮叫「清理」，与悬停按钮「拉黑」是同一动作却两个名字 | 「清理」统一改名「拉黑」，默认中性，悬停才变红；DS 角标降饱和 |
| 计数条 | 切换深色后不跟随（深色类只在文字变化时才切换）；样式偏平 | 每次更新都同步深色类；加小圆点与等宽数字 |

> 未做：设置面板（popup）的版式问题——标题折行、总开关被挤扁、屏蔽词/名单页按钮竖排与横向溢出，计划下一轮处理。
